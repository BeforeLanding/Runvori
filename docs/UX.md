## 1. 信息结构

首版保留五个主要页面：连接与配对、会话列表、会话详情、审批详情、回合结果。诊断与解除配对放在设置入口。差异与命令输出作为回合结果下的产物详情子页，不增加独立项目管理工作台。

### 连接与配对（FR-01）

- 未配对时展示准备步骤、扫描入口和手动粘贴配对信息入口；手动方式必须包含同样的 Host 身份信息。
- 扫描后展示 Host 别名、地址和身份摘要，用户确认后交换凭据。不能通过“忽略证书错误”继续。
- 区分地址不可达、TLS 身份不符、秘密过期、已有配对设备、协议不兼容；说明可在电脑完成的修复动作。
- Host 地址变更需重新核对身份，不自动信任相同名字的服务。

### 会话列表（FR-02、FR-06）

- 顶部展示 Host 名、连接状态及最后同步时间；全局活动回合保持可定位。
- 每行展示会话标题、工作区别名、最新回合状态、待审批数和更新时间，不以闪烁/颜色作为唯一提示。
- 空态为“请在电脑上通过 Runvori 启动首个会话”，不要展示无法使用的手机新建工作区按钮。
- 离线时展示缓存并标“上次同步”；加载失败保留旧内容，可手动刷新。

### 会话详情（FR-03、FR-05、FR-08）

- 顶部固定连接状态、回合状态和待审批入口；正文为按项组织的时间线。
- 命令显示可展开的命令、cwd、状态、退出码及输出；大输出按页读取，文件改动可打开差异。
- “中断”属于当前活动回合；点击二次确认“停止当前回合；已产生的文件改动保留”。提交后显示正在中断。
- 无活动回合且同步完成后展示“继续此会话”输入框；发送是新回合，旧结果可继续查看。活动期间不提供队列或中途追加输入。
- 被中断回合展示原因和“可在此会话发起新回合”，不能使用“从断点继续执行”。

### 审批详情（FR-04）

- 显示工作区、操作种类、原因、真实命令/cwd 或变更文件、差异预览和“仅本次”。
- 长内容允许展开、横向查看与复制；批准前必须能够访问完整可用内容，内容缺失/不支持时禁用允许并提供中断入口。
- 按钮文案为“允许本次”“拒绝”。离线、不同步、版本过期、未知类型或请求已处理时不可操作。
- 决定受理后禁用重复按钮，保留用户刚才的选择和时间；失去响应时提示刷新核对，不提示再次批准。
- 原请求已结束时保留卡片历史；用户能跳转到相关命令或改动结果。

### 回合结果（FR-07）

- 分别显示“回合完成/失败/中断”和“验证通过/失败/未运行/结果未知”。
- 按必需验证项列出命令、cwd、退出码、执行时间、证据入口。Agent 总结单独标记为“Agent 摘要”。
- 差异标明来源：“审批提案”“上游报告完成”或“Git 工作区快照”。Git 快照固定标注“可能包含回合前已有改动、归因未知”，不能默认为本回合产生。
- 对二进制、大文件、截断输出、未跟踪文件、产物丢失和不可用退出码显示原因；不把空面板当作“没有改动”。产物正文按块读取，显示已读/总字节与“加载更多”，不能自行跳块。

## 2. 稳定阅读

两种阅读模式：

- 跟随最新：用户原本在末尾或主动点击“回到最新”；批量刷新后才跟随末尾。
- 浏览历史：用户向上滚动即进入；新增内容只更新提示，不改变可见位置。

锚点保存 `(host_id, session_id, run_id, item_id, anchor_seq, offset_px, follow_latest)`。列表使用稳定 item ID，事件 seq 用于重放与定位，不把数组下标当稳定键。相同 item 的流式文本增长也必须保留其内部阅读位置。

向上加载历史前记录首个可见条目与偏移，插入后恢复同一锚点；批量更新不要每个 token 重组整屏。首轮按最多约每 100 ms 合并 UI 更新，最终数值由性能测量调整；终态和审批优先刷新。

旋转屏幕/进程重建后，从本地缓存重建列表，再异步同步；锚点页未加载时显示定位中并读取对应历史。条目已不可用时定位最近保留条目，明确提示，不直接拉到最底部。

新增提示按“项”计数，避免 token 数冒充消息数；点击后进入跟随最新。新审批可显示顶部提示和导航入口，不能强行打断当前阅读。

## 3. 状态与文案

回合文案：starting“正在启动”；running“执行中”；waiting_approval“等待审批”；interrupting“正在中断”；completed“回合已完成”；failed“回合失败”；interrupted“回合已中断”。

连接文案：online“已连接”；reconnecting“正在重新连接”；offline“离线，显示上次同步内容”；unauthorized“配对凭据已失效，请在电脑重新配对”；incompatible“版本不兼容，请更新后重连”。

审批文案：pending“等待决定”；decision_recorded“决定已收到，等待发送”；dispatching“等待 Codex 处理”；resolved“请求已处理，请查看执行结果”；expired“请求已失效”；unknown“决定可能已送达，正在核对”。不能把 resolved 显示为“命令成功”。

每次进入前台或连接中断，先关闭写入口，待认证、事件和审批同步完成再开放。后台期间不承诺通知/长连接；离线不保存待发送决定。已发送请求的 request_id 必须保留，以便查询原操作。

## 4. 错误反馈

- 操作冲突：保留原内容，刷新真实状态，说明“状态已变化”。
- 确认丢失：保持处理中/不确定，查询同一 request_id，不创建新的批准。
- Host 重启：展示旧回合中断原因；执行环境未就绪时，继续输入不可用。
- 数据过大：分块/摘要并提供原始可用内容入口；审批关键内容不可得则不能允许。
- 存储不足：解释本地缓存还是 Host 存储不足；缓存写失败不推进游标。
- 内容缺失：保留占位与来源信息，允许重试查询，不默默删除历史。

## 5. 可访问性与交互验证

关键按钮采用 Android 可访问触控尺寸，带文字和语义标签；状态同时使用文字与图形。支持 TalkBack 顺序阅读和 200% 字体，长命令可复制且不覆盖审批按钮。正文与代码区遵循系统明暗主题，权限含义不依赖颜色。

交互验收使用真实安装版本：长文本/代码、大差异、空态、断网、旋转、后台、进程重建、审批过期、Host 重启。具体步骤与性能阈值见 [TEST_PLAN.md](TEST_PLAN.md)。
