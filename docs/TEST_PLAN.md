# 测试、验收与证据计划

日期：2026-10-23。状态：测试设计，所有用例尚未执行，不代表通过。需求来源：[PRD](PRD.md)。

DEV-001 补充：已建立 stdio 探针的合成故障测试和真实握手检查，见 [本轮证据](evidence/DEV-001.md)；它们是 M0 前置检查，本文 AT 产品验收仍未执行。

## 1. 验证层次

- 领域单元测试：回合/审批状态迁移、验证汇总、版本检查、阅读模式与事件归并。
- SQLite 集成测试：事件和快照事务、单活动槽、幂等记录、并发决定、崩溃恢复和迁移。
- API 契约测试：认证、分页、限额、错误模型、长轮询与写操作语义，不依赖真实模型。
- Codex 适配器测试：基于锁定版本的脱敏 schema/消息夹具；普通 CI 使用确定性模拟，不读取开发者认证。
- Android 测试：领域归并、Room 事务、ViewModel、Compose 关键流程和实机性能。
- 真实端到端：固定 CLI、Host、设备和可重置仓库，包含真实审批、命令与退出码；由显式配置的本地环境执行。

不要只依赖录屏或 mock。录屏证明交互，结构化日志与数据库检查证明状态，真实命令和退出码证明执行结果。

## 2. 需求验收用例

### AT-01 配对、撤销与 Host 身份（FR-01、NFR-02）

使用有效秘密配对，验证只有一个有效设备；重放秘密、过期秘密、第二台手机、限流与错误指纹均被拒绝。撤销后旧设备读写返回 401，进行中的长轮询被终止。交换响应丢失后只允许本地撤销重配，不能重复获取令牌。

证据：脱敏 API 结果、设备代次变化、无敏感信息的访问日志。TLS 不匹配不能通过“跳过检查”成功。

### AT-02 会话归属与列表（FR-02）

本地启动登记工作区中的会话，检查列表、分页和快照；运行在 Host 外部的 Codex thread 不出现在受管集合。手机不能创建任意工作区，伪造 session/run/artifact ID 不能跨资源读取。

### AT-03 时间线与内容（FR-03）

回放文本、命令、文件改动、审批和异常，检查顺序、item 聚合和输出完整性。超过块/页限额时正确分块；超大正文转产物并明示截断/不可用。混合 UTF-8 字符跨块解码无乱码。

### AT-04 正常单次审批（FR-04、NFR-01）

分别触发命令和文件审批，核对真实操作、范围与原因。允许/拒绝仅作用于本次。Host 受理后 UI 先显示处理中；上游请求结束和命令结果分别显示。审批被拒绝不应被渲染为执行成功。

### AT-05 重复、冲突和丢失确认（FR-04、NFR-01）

对同一审批双击、相同 request_id 重试、不同标识相同决定、相反决定及版本过期分别测试。只接受一个决定；同 key 不同请求返回冲突。模拟 Host 已记录决定但 HTTP 响应丢失，重连查询原操作，不二次派发。

进一步在“事务提交前、提交后、领取派发后、上游发送后、确认落库前”注入终止。检查旧 epoch 决定不重放；无法判定的结果显示 unknown。统计上游实际收到的响应次数，不能仅检查手机按钮被禁用。

### AT-06 失效与未知审批（FR-04、NFR-02）

等待审批时结束/中断回合、重启 app-server，再提交旧请求，应失效且不能批准新 epoch 的同号请求。注入不支持的控制请求和缺失命令/差异内容，允许按钮不可用；安全拒绝或中断并给出原因，不形成无限等待。

### AT-07 中断与终态竞争（FR-05）

从 running、waiting_approval、starting 请求中断；重复中断返回已有结果。模拟完成与中断竞争、RPC 失败和确认丢失。只有真实终态或确定的进程停止才显示已中断；已经完成则仍显示 completed，文件改动保持可检查。

### AT-08 单活动回合与启动幂等（FR-02、NFR-01）

手机和本地入口同时发起回合，仅一个获得活动槽；starting 和 interrupting 同样占槽。启动已发送但确认丢失时禁止第二次启动；重复 key 返回原操作。尝试第二 Host 实例/多 worker 配置，应拒绝产生双执行。终态重复事件不清空其他回合的槽。

### AT-09 断网和事件同步（FR-06、NFR-01）

执行期间断网 30 秒再恢复，比较 Host 已提交事件与客户端连续游标、去重后的序列和内容哈希，必须一致。注入重复页、事件缺口、空轮询、落后游标、超前游标和身份变化。客户端不能跳过缺口推进，也不能将两个 Host 的数据合并。

离线审批/中断/后续输入不可提交，重连前不启用旧审批；Host 执行不因手机离线被错误标失败。

### AT-10 Android 生命周期（FR-06）

分别旋转、切后台、系统杀进程、清除缓存后重新打开。保留缓存的场景恢复正确会话与锚点；清除缓存后重新读取，不伪造恢复成功。模拟 Room 写事务失败，游标不得超过已落盘事件。

后台不要求审批实时到达；回到前台必须核对当前审批与原未确认操作后才开放写入口。

### AT-11 阅读与可访问性（FR-03、FR-06、NFR-03、NFR-04）

用户浏览历史时持续追加事件、更新同一长消息、向前分页、旋转并重建进程，检查同一 item 与内部偏移保持；“回到最新”进入跟随模式。长代码、200% 字体、TalkBack、明暗主题及错误提示均可用。量化方法见下文。

### AT-12 安全与数据清理（FR-01、FR-10、NFR-02）

检查令牌/配对秘密不进 URL、普通日志、诊断包与备份；未认证的所有业务接口被拒绝。测试 `..`、同前缀目录、符号链接、Windows junction、编码路径和伪造产物 ID，不能读工作区外文件。未知审批不扩权。

终态会话本地删除后事件/操作/产物移除，活动会话删除被拒绝；手机清缓存不影响 Host，撤销配对清手机凭据。恢复旧数据库备份后身份与凭据变更，旧缓存不静默续接。

### AT-13 结果与验证真实性（FR-07）

准备测试通过、退出码非零、未配置验证、配置后未执行、退出码缺失、中途终止、非验证命令失败等案例。检查 required 验证项的映射和汇总规则。模型输出“全部通过”但没有真实证据时仍为 not_run/unknown；回合 completed 可以同时验证 failed。

### AT-14 差异来源（FR-07）

准备干净/脏工作区、未跟踪文件、重命名、二进制和大差异；检查回合前基线、上游改动和当前 Git 差异的标签。无法分离的改动不归因于 Agent。产物缺失或截断必须可见，不能显示空白通过。

### AT-15 历史新回合（FR-08）

完成一次任务后加载原 thread，明确发送新输入，生成新的 run/turn，保留旧结果。工作区丢失、thread 不可加载和已有活动回合时返回明确错误。仅重新打开手机不会启动任何新回合。

### AT-16 Host/上游重启（FR-09、NFR-01）

在 starting、running、等待审批、决定派发和中断过程中终止 Host/app-server。重启后保留已提交事件，旧回合标 interrupted 且带原因，旧审批不可再用，不自动重跑。确认遗留进程停止/隔离前保持只读，不开放新执行。

检查崩溃前未落盘输出的说明和不确定操作；不能在没有证据时把整段执行称为已恢复。以真实首发 OS 进行进程树验证，不能仅使用 mock PID。

### AT-17 容量与故障（FR-10、NFR-01、NFR-02）

模拟队列满、数据库只读/忙、磁盘不足、产物写入中断和损坏资源。不得发布未提交事件，不得让文件元数据引用未完成产物。拒绝新回合，安全停止受管执行；无法落盘时显示故障，恢复后记录中断和可能缺失范围。诊断信息不泄露正文与凭据。

## 3. 性能测量方法

M0 冻结基准机，记录型号、CPU/内存、Android 版本、刷新率、字体/显示缩放、电源和温度条件，以及 APK 构建/提交、Host OS/版本、CLI、网络 RTT。使用 release/profileable 构建，不使用带调试器的结果作为发布证据。

数据集：10,000 条脱敏事件，总正文约 20 MiB，包含长消息、命令、审批和差异。开始时加载历史页，执行固定滚动脚本并持续以 20 条/秒追加；至少 20 次独立测量，保存原始数据和测试种子。

- 帧：用 Android 系统帧统计/性能跟踪，报告帧耗时 p50/p95/p99 与卡顿比例；60 Hz 基线下 p95 ≤32 ms、卡顿帧（超过一个刷新周期）≤5%。说明统计工具及口径。
- 内存：记录稳态和峰值 PSS，峰值 ≤250 MiB，并检查重复进入会话后的持续增长。
- 锚点：固定手势与锚点 item，比较刷新前后同一条目位置；静态阅读期间误差 ≤8 dp。主动滚动与屏幕布局变化不混入该误差统计。
- 恢复：RTT ≤50 ms，已配对客户端落后 1,000 条、约 1 KiB/条，从恢复连接开始到连续游标追平且审批刷新为止，p95 ≤3 秒；大产物下载另测，不计入该小事件基准。
- 审批：从 Host 收到请求到操作持久受理响应，p95 ≤500 ms；另记录上游确认与实际执行耗时，不混为 Host 接收耗时。

p95 使用排序后的 nearest-rank；次数、失败和异常值全部披露。首轮不达标应定位瓶颈并在决策记录中解释，不能只删异常运行或更换更快设备。

## 4. 可重置端到端演示

使用不含秘密的小型代码仓库，提供固定初始提交、故障和验证命令；每轮演示使用可丢弃副本，保留目标路径保护，禁止重置用户真实项目。

演示顺序：

1. 本地启动修复任务，手机连接并读时间线。
2. 浏览历史时持续输出，展示不跳动及回到最新。
3. 触发一次真实命令/文件审批，展示操作内容与处理结果。
4. 断网/切后台后返回，展示无重复事件和最新审批。
5. 展示差异、实际测试命令、退出码和验证汇总。
6. 在原会话发起新回合；另录验证失败、主动中断与 Host 重启边界。

完整主链路连续成功 10 次；失败轮次保留，修复后重新连续计数。首次真实模型运行的成本、网络和权限由本地测试环境负责，普通 CI 不自动触发真实账号访问。

## 5. 证据与发布检查

计划将脱敏证据放入 `docs/evidence/<版本>/` 或发布附件；当前未创建该目录，也没有通过记录。每条记录至少包含：提交 SHA、需求/AT 编号、环境、步骤、输入数据、实际结果、日志/录屏/指标位置、执行日期和未解决问题。

CI 建立后必跑领域/数据库/协议/客户端单元与构建检查；设备和真实 Codex 验收按发布候选版执行。迁移需有旧数据库样本和前向升级检查，不默认支持数据库降级。

阻断发布：错误批准、未经授权访问、事件丢失、重复执行、终态误报、敏感信息泄露，以及无法安全隔离的遗留进程。其余问题逐项评估，未通过项不能从验收记录中删去。发布条件以 [PRD 第 7 节](PRD.md#7-发布与成功判定) 为准。
