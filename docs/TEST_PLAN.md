## 1. 验证层次

- 领域单元测试：回合/审批状态迁移、验证汇总、版本检查、阅读模式与事件归并。
- SQLite 集成测试：事件和快照事务、单活动槽、幂等记录、并发决定、崩溃恢复和迁移。
- API 契约测试：认证、分页、限额、错误模型、长轮询与写操作语义，不依赖真实模型。
- Codex 适配器测试：基于锁定版本的脱敏 schema/消息夹具；普通 CI 使用确定性模拟，不读取开发者认证。
- Android 测试：领域归并、SQLite 缓存事务（`SQLiteOpenHelper`，未采用 Room）、ViewModel、Compose 关键流程和实机性能。
- 真实端到端：固定 CLI、Host、设备和可重置仓库，包含真实审批、命令与退出码；由显式配置的本地环境执行。

不要只依赖录屏或 mock。录屏证明交互，结构化日志与数据库检查证明状态，真实命令和退出码证明执行结果。

## 2. 需求验收用例

### AT-01 配对、撤销与 Host 身份（FR-01、NFR-02）

使用有效秘密配对，验证只有一个有效设备；重放秘密、过期秘密、第二台手机、限流与错误指纹均被拒绝。撤销后旧设备读写返回 401，进行中的长轮询被终止。交换响应丢失后只允许本地撤销重配，不能重复获取令牌。

证据：脱敏 API 结果、设备代次变化、无敏感信息的访问日志。TLS 不匹配不能通过“跳过检查”成功。

DEV-006 部分覆盖（2026-10-27）：合成 HTTPS 闭环验证了错误 SPKI 指纹不发出任何请求、有效秘密配对成功、同秘密重放 409、第 6 次交换 429 且有 `Retry-After`、运行中撤销后业务请求 401 且在途长轮询被终止。未覆盖：过期秘密、第二台手机、交换响应丢失后的人工重配（旧回环探针仍覆盖重放拒绝）、访问日志审计与 Android 信任。见 [证据](evidence/DEV-006-https-host.md)。

DEV-007 部分覆盖（2026-10-27）：`GET /v1/sessions` 已实现并被真实 APK 使用——设备验收的 `b` 场景从手机列出 Host 登记的两个会话并打开其一；Host 侧 `test_host_timeline.py` 验证游标按 `session_id` 稳定分页、返回最近回合与待审批计数。未覆盖：运行在 Host 之外的 Codex thread 不出现在列表、伪造 ID 的跨资源读取、分页在真机上的连续翻页。见 [证据](evidence/DEV-007-device-acceptance.md)。同日真实 Codex 设备验收也从手机列出两个会话并打开 `devsess0`，见 [真实设备验收](evidence/DEV-007-device-acceptance-real.md)。

### AT-03 时间线与内容（FR-03）

### AT-04 正常单次审批（FR-04、NFR-01）

分别触发命令和文件审批，核对真实操作、范围与原因。允许/拒绝仅作用于本次。Host 受理后 UI 先显示处理中；上游请求结束和命令结果分别显示。审批被拒绝不应被渲染为执行成功。

DEV-006 部分覆盖（2026-10-27）：合成上游的 HTTPS 闭环验证命令审批详情含 command、cwd 在登记工作区内、`allowed_decisions=[allow_once,deny]`；决定受理 202，操作最终 `confirmed/request_closed`。文件审批缺少 item 证据时 `details_status=insufficient`，允许 409、拒绝 202。真实 Codex 一次回合同样验证了详情完整性与决定链路，但 Windows 命令串带 shell 包装，未宣称与探针字面量一致。

DEV-007 补充（2026-10-27）：真实 APK 在设备验收 `b` 场景完成一次完整审批：审批页展示上游给出的完整命令串与 cwd（原样展示，不简化成裸命令），`details_status=complete`，允许按钮可用；双击只产生**一个**决定操作（缓存中 `kind=approval` 的操作数断言为 1），提交后 202 文案是“Host 已受理，等待发送与处理”，随后操作经 `/v1/operations?kind=approval` 轮询到终态、审批转 `resolved`、回合转终态，时间线出现命令与输出。`f` 场景验证 `insufficient` 的文件审批只给拒绝。**真实文件审批的 `complete` 路径仍未覆盖**（设备的 `f` 走合成 `insufficient`），`command_matches_probe=false` 依旧成立。见 [设备验收](evidence/DEV-007-device-acceptance.md)。

DEV-007 真实验收补充（2026-10-27）：真实 Codex 设备验收的 `b` 场景完成一次真实命令审批：详情 `complete`、命令非空、cwd 在登记工作区内、允许/拒绝可用；双击只产生一个操作，`allow_once` 后操作 `confirmed`、审批 `resolved`、回合 `run.completed`，时间线命令 exit 0 且输出非空。真实命令串可能带 shell 包装，本轮 `command_match_asserted=false`，不宣称与探针字面量一致。见 [真实设备验收](evidence/DEV-007-device-acceptance-real.md)。

### AT-05 重复、冲突和丢失确认（FR-04、NFR-01）

对同一审批双击、相同 request_id 重试、不同标识相同决定、相反决定及版本过期分别测试。只接受一个决定；同 key 不同请求返回冲突。模拟 Host 已记录决定但 HTTP 响应丢失，重连查询原操作，不二次派发。

进一步在“事务提交前、提交后、领取派发后、上游发送后、确认落库前”注入终止。检查旧 epoch 决定不重放；无法判定的结果显示 unknown。统计上游实际收到的响应次数，不能仅检查手机按钮被禁用。

DEV-007 补充（2026-10-27）：设备验收 `b` 场景在真实 APK 上对同一审批连点两次——第一次点击后两个按钮立即不可用，紧接着再调用一次决定入口，缓存中的 `kind=approval` 操作数仍为 **1**。`g` 场景对同一 `request_id` 连续查询两次，状态一致。未覆盖：不同标识的相同/相反决定、版本过期冲突的 UI 呈现、HTTP 响应丢失后的原操作核对，以及“上游实际收到几次”的服务端计数。

### AT-06 失效与未知审批（FR-04、NFR-02）

等待审批时结束/中断回合、重启 app-server，再提交旧请求，应失效且不能批准新 epoch 的同号请求。注入不支持的控制请求和缺失命令/差异内容，允许按钮不可用；安全拒绝或中断并给出原因，不形成无限等待。

DEV-006 补充（2026-10-27）：详情不足、被截断、cwd 无法证明在登记工作区内、类型非普通命令，或 v13 旧审批迁移后，`allow_once` 均返回 409 `approval_details_insufficient`，只保留拒绝；由 `test_approval_details.py` 与合成 HTTPS 闭环覆盖。未知控制请求仍按既有规则关闭连接并恢复。

DEV-007 补充（2026-10-27）：设备验收 `d` 场景在真实 APK 上验证——请求被上游结束、审批转 `expired` 后，UI 的允许与拒绝**都不可用**（`can_allow=false`、`can_deny=false`），绕过 UI 直接用 API 对同一审批提交 `allow_once` 被 Host 拒绝。`c` 场景验证回合终态后重连不会让旧审批重新可用。未覆盖：等待审批时重启 app-server 使新 epoch 复用同号请求。真实模式本轮未跑 `d`；真实中断/过期需要第二次显式授权的模型回合。

DEV-009 真实运行（2026-10-30，`ra` 首次 1 个回合 + 复跑 1 个回合，均未重试）：真实审批页保持打开，通过产品中断入口结束回合。复跑手机侧通过——旧审批为 `expired`、允许与拒绝不可用、绕过 UI 的 `allow_once` 被 `approval_expired` 拒绝、缓存审批操作数为 0；Host 侧 run 为 `interrupted`、中断操作 `confirmed/run_interrupted`、活动槽释放、`pending_approvals=0`、`approval_operations=0`，事件历史保留回合终止导致的 `expired`。首次运行中真实 Codex 在回合终止后又关闭上游请求，把当前 `resolution_kind` 改写为 `request_closed`，首次分类器只接受最终 `turn_terminal`，因此判失败并停止；证据读取器已改为从事件历史确认回合终止失效并允许其后的 `request_closed`，随后单独授权的 1 个回合复跑通过。首次失败报告保留，不追溯改写。合成伴侣 `s3` 已在真实 APK + 合成上游上通过。见 [验收结果](evidence/DEV-009-interrupt-approval-real.md) 与 [运行方案](evidence/DEV-009-interrupt-approval-plan.md)。

### AT-07 中断与终态竞争（FR-05）

从 running、waiting_approval、starting 请求中断；重复中断返回已有结果。模拟完成与中断竞争、RPC 失败和确认丢失。只有真实终态或确定的进程停止才显示已中断；已经完成则仍显示 completed，文件改动保持可检查。

DEV-009 首次真实运行（2026-10-30，`ri` 1 个模型回合，未重试）：真实命令输出 `RUNVORI_SLEEP_STARTED` 后手机请求中断，同一 run 终态为 `run.interrupted`，中断操作 `confirmed/run_interrupted`，活动槽释放，手机场景通过。自然完成仍记 `terminal_race_natural_completion`，RPC 返回或 202 单独不算证据。离线覆盖触发超时、终态超时、终态竞争与未确认中断。该路径只覆盖运行中中断；`starting` 中断、真实并发竞争、RPC 失败和确认丢失仍需分别验证。见 [运行方案](evidence/DEV-009-interrupt-approval-plan.md)。

### AT-08 单活动回合与启动幂等（FR-02、NFR-01）

手机和本地入口同时发起回合，仅一个获得活动槽；starting 和 interrupting 同样占槽。启动已发送但确认丢失时禁止第二次启动；重复 key 返回原操作。尝试第二 Host 实例/多 worker 配置，应拒绝产生双执行。终态重复事件不清空其他回合的槽。

### AT-09 断网和事件同步（FR-06、NFR-01）

执行期间断网 30 秒再恢复，比较 Host 已提交事件与客户端连续游标、去重后的序列和内容哈希，必须一致。注入重复页、事件缺口、空轮询、落后游标、超前游标和身份变化。客户端不能跳过缺口推进，也不能将两个 Host 的数据合并。

离线审批/中断/后续输入不可提交，重连前不启用旧审批；Host 执行不因手机离线被错误标失败。

DEV-006 部分覆盖（2026-10-27）：合成闭环在一次完整回合后，用新客户端从 `after_seq=0` 补齐 12 条事件，验证 seq 连续且无重复；协同的 `next_after_seq`/`has_more` 由既有邮箱测试覆盖。未覆盖：真实断网 30 秒、缺口/超前/身份变化注入、客户端缓存事务与 Android 重连顺序。

DEV-007 补充（2026-10-27）：设备验收的 `c` 场景在真实 APK 上制造历史后丢弃内存连接，用新建 ViewModel 从磁盘游标重同步，断言缓存事件 seq 无重复、从 1 连续、`syncGap=false` 且终态事件仍在。这是**进程内重建**，不等于系统杀进程或断网 30 秒；缺口、超前游标与身份变化的注入仍未在设备侧覆盖。真实 Codex 设备验收的 `c` 复用 `b` 已写入 `devsess0` 的历史重同步，不额外产生模型回合，见 [真实设备验收](evidence/DEV-007-device-acceptance-real.md)。

DEV-010 补充（2026-10-30，模拟器）：`off` 在 Host 被停止后启动真实 APK，展示缓存会话与时间线，`writable=false`、发送入口不存在，编程 `startRun` 被拒且缓存操作数不变；`rec` 在 Host 同端口、同数据目录、同证书重启后从游标重拉，seq 连续、无重复、无缺口，终态事件仍在。Host 侧 `runs`/`approval_operations` 在离线与恢复期间不变。这不是真实 Wi-Fi/移动数据断开 30 秒，也不证明物理手机可达；见 [DEV-010 证据](evidence/DEV-010-device-baseline.md)。

### AT-10 Android 生命周期（FR-06）

分别旋转、切后台、系统杀进程、清除缓存后重新打开。保留缓存的场景恢复正确会话与锚点；清除缓存后重新读取，不伪造恢复成功。模拟缓存写事务失败，游标不得超过已落盘事件。

后台不要求审批实时到达；回到前台必须核对当前审批与原未确认操作后才开放写入口。

DEV-007 部分覆盖（2026-10-27）：设备验收 `c` 场景丢弃内存中的 `HostSession`/ViewModel，保留磁盘缓存后新建 ViewModel 重连，得到正确的会话、连续游标与终态事件。这只等价于“进程内重建”，**不是**系统杀进程；旋转、切后台、清除缓存、缓存写事务失败（本实现用 `SQLiteOpenHelper`，未采用 Room，尚无注入写失败的用例）均未执行。

DEV-010 补充（2026-10-30，模拟器）：`o` 覆盖切后台与进程重建后的审批恢复并等待写门打开后决定；`y/z` 分别记录系统 `am kill` 与 `force-stop` 后审批恢复，Host `runs`/`approval_operations` 计数不变；`off/rec` 覆盖 Host 不可达时的只读缓存与恢复。清除缓存、真实物理设备和所有厂商进程管理行为仍未覆盖。

## 3. 性能测量方法

M0 冻结基准机，记录型号、CPU/内存、Android 版本、刷新率、字体/显示缩放、电源和温度条件，以及 APK 构建/提交、Host OS/版本、CLI、网络 RTT。使用 release/profileable 构建，不使用带调试器的结果作为发布证据。

数据集：10,000 条脱敏事件，总正文约 20 MiB，包含长消息、命令、审批和差异。开始时加载历史页，执行固定滚动脚本并持续以 20 条/秒追加；至少 20 次独立测量，保存原始数据和测试种子。

- 帧：用 Android 系统帧统计/性能跟踪，报告帧耗时 p50/p95/p99 与卡顿比例；60 Hz 基线下 p95 ≤32 ms、卡顿帧（超过一个刷新周期）≤5%。说明统计工具及口径。
- 内存：记录稳态和峰值 PSS，峰值 ≤250 MiB，并检查重复进入会话后的持续增长。
- 锚点：固定手势与锚点 item，比较刷新前后同一条目位置；静态阅读期间误差 ≤8 dp。主动滚动与屏幕布局变化不混入该误差统计。
- 恢复：RTT ≤50 ms，已配对客户端落后 1,000 条、约 1 KiB/条，从恢复连接开始到连续游标追平且审批刷新为止，p95 ≤3 秒；大产物下载另测，不计入该小事件基准。
- 审批：从 Host 收到请求到操作持久受理响应，p95 ≤500 ms；另记录上游确认与实际执行耗时，不混为 Host 接收耗时。

p95 使用排序后的 nearest-rank；次数、失败和异常值全部披露。首轮不达标应定位瓶颈并在决策记录中解释，不能只删异常运行或更换更快设备。

## 4. 可重置端到端演示

使用不含秘密的小型代码仓库，提供固定初始提交、故障和验证命令；每轮演示使用可丢弃副本，保留目标路径保护，禁止重置用户真实项目。

演示顺序：

1. 本地启动修复任务，手机连接并读时间线。
2. 浏览历史时持续输出，展示不跳动及回到最新。
3. 触发一次真实命令/文件审批，展示操作内容与处理结果。
4. 断网/切后台后返回，展示无重复事件和最新审批。
5. 展示差异、实际测试命令、退出码和验证汇总。
6. 在原会话发起新回合；另录验证失败、主动中断与 Host 重启边界。

完整主链路连续成功 10 次；失败轮次保留，修复后重新连续计数。首次真实模型运行的成本、网络和权限由本地测试环境负责，普通 CI 不自动触发真实账号访问。
