# DEV-005 新回合一次派发与 stdio 绑定切片

日期：2026-10-25。需求关联：FR-02、FR-08、FR-09；路线图：M0 兼容映射与 M1 新回合派发。项目仍处 M0。

## 行为

- 对已持久受理的 run 操作，使用原 session、run、请求版本和输入重放幂等摘要；内容不一致拒绝。输入原文由受信任本地调用方提供，事件库只持久保存摘要。当前调用方也提供 thread ID；完整产品 Host 尚须持久约束 session 与 thread 的归属。
- 校验当前 epoch 后，单库先提交 `dispatching` 领取，再发送 `turn/start`。响应包含非空 `turn.id` 时，单库将该 thread/turn 与 run 绑定，操作记 `confirmed/turn_started`。审批请求若早于 RPC 响应到达，stdio 缓冲保留该消息，绑定提交后再按顺序持久化。
- 响应丢失、形状错误或绑定事务失败时关闭上游连接，将已领取操作记 `unknown`；活动槽和 `starting` 回合保持，等待隔离恢复。重复派发不再发送。

## 验证与限制

`python scripts/check.py`：16 份契约通过；175 项测试运行，170 通过、5 项因本环境链接创建或回环连接限制跳过。测试覆盖审批请求先于响应、输入摘要冲突、领取事件失败无发送、上游不回复/回复畸形、绑定事件失败回滚及重复派发拒绝。

`scripts/smoke_package.ps1`：离线 wheel 构建、隔离安装、已安装 CLI 的 16 份契约核对及新增模块导入通过。

尚无产品 Host 的 session/thread 归属表、受管进程生命周期及真实锁定 CLI 联调；合成 peer 不能证明真实上游在所有竞态中都按相同顺序发出消息。明确的上游 RPC 错误目前保守记未知，未单独证明“从未启动”。
