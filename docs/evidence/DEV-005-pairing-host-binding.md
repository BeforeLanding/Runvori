# DEV-005 配对凭据与 Host 身份绑定

日期：2026-10-26。需求关联：FR-01、FR-06；路线图：M1 Host 认证前提。项目仍处 M0。

## 行为

- 配对库的一次性秘密和设备令牌现在必须携带合法 `host_id`。使用其他 Host 身份兑换秘密会被拒绝且不消费原秘密；令牌认证同时核对摘要、有效设备槽和 Host 身份。
- 旧配对库增加身份列后，无归属的一次性秘密被删除、有效设备令牌被撤销。迁移中断后再次打开仍会处理残留的空身份记录；不会把旧凭据猜作当前 Host 的凭据。
- 内部读取网关由受信任的 Host 组合层提供当前持久 `host_id`，并用其认证每次读取。新 Host 数据库生成不同身份后，旧配对令牌在进入事件邮箱前被拒绝；本地撤销后可明确重新配对。

## 验证与限制

`python scripts/check.py`：16 份契约通过；276 项测试运行，271 通过、5 项因本环境链接创建或回环连接限制跳过。新增 4 项行为测试覆盖错误 Host 的秘密兑换、旧无归属凭据迁移、迁移失败回滚/重试和新 Host 身份下的读取拒绝。`.\scripts\smoke_package.ps1`：离线 wheel 构建、隔离安装、已安装 CLI 契约校验和模块导入通过。

受影响的 `python scripts/probe_https_pairing.py` 已尝试运行，但本环境返回 `loopback_unavailable`，因此本轮没有新的真实回环 HTTPS 联动证据；该限制和既有处理见 [错误记录](../ERRORS.md)。

当前没有产品 Host 组合层、HTTPS 配对 API、证书身份绑定或 Android 联调。读取网关必须由持有当前 Host 数据库身份的可信启动路径构造；若调用方传入过时身份，单靠配对库无法察觉。旧备份回滚检测与身份轮换仍需独立恢复流程，不能仅靠此字段证明安全恢复。
