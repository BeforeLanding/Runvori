## 实现与依据

使用 Python ctypes 调用 Windows Job Object，设置 KILL_ON_JOB_CLOSE；Job 句柄不继承。Host 启动内部 bootstrap，先分配到 Job，再通过 stdin 的单字节门控放行目标命令；门控使用原始读取，避免预读后续 JSONL。分配失败时终止启动器，不放行目标。

直接子进程退出后仍关闭 Job，清理持有输出管道的后代；Host 强制退出由 Windows 关闭其句柄触发清理。正常关闭先给予 stdin EOF，随后关闭 Job，不再按 PID 查找或调用 taskkill。

Windows 默认将普通 CreateProcess 子进程归入 Job，kill-on-close 是生命周期管理机制。经外部服务/WMI 创建进程的行为不受该继承承诺覆盖；Job 也不替代用户权限和 Codex 沙箱。[Microsoft Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
