# DEV-005 审批与事件库持锁启动切片

日期：2026-10-25。需求关联：FR-02、FR-09；路线图：M1 单实例锁与 Host 持久化。当前仍处 M0，本切片不是可对手机提供服务的产品 Host。

## 实现与边界

- 新增 `LockedHostJournals`：调用方提供已存在的绝对数据目录，先取得同一个 Windows `host.lock`，然后顺序打开 `approvals.db` 与 `events.db`。争锁失败时两个 SQLite 构造器都不调用；第二个库打开失败时关闭第一个库并释放锁；正常关闭先关库再释放锁。
- 该类不会推进审批 epoch，也不会调用事件库的回合恢复。持锁进程异常退出后，后继进程可以重开数据库，但旧活动槽和审批 epoch 原样保留，须先核对并隔离旧 app-server 才能执行恢复。
- 本阶段两个库仍是独立 SQLite 文件，只验证启动所有权与资源清理；后续单库切片改用共享连接，并拒绝静默忽略这里产生的双库数据，见 [记录](DEV-005-unified-store.md)。本阶段不能对审批、事件和活动槽提供跨库原子事务。

## 验证

执行 `python scripts/check.py`：16 份契约通过；131 项测试运行，126 通过、5 项因本环境链接创建或回环连接限制跳过。新增 3 项 Windows 行为测试覆盖争锁前不打开任一数据库、第二库失败后释放第一库与锁，以及真实持锁进程被终止后重开仍保留活动槽和原审批 epoch。
