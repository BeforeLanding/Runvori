# DEV-005 单库审批请求事务切片

日期：2026-10-25。需求关联：FR-02、FR-04、FR-09；路线图：M1 单库持久化与审批状态。项目仍处 M0，本记录只证明本地存储行为。

## 实现与兼容边界

- `LockedHostJournals` 先取得 Windows 单实例锁，再用 `host.db` 的一个 SQLite 连接打开事件库与审批记录。原 `ApprovalJournal(path)` 独立探针入口继续可用；通过共享连接创建时，它不拥有也不单独关闭该连接。
- 新启动路径若发现旧切片的 `approvals.db` 或 `events.db`，立即拒绝，既不创建新的 `host.db`，也不移动或删除旧数据。当前没有从双库探针到单库的迁移工具；需要保留旧库以供人工核对，不能静默当作空 Host。
- 在已有且处于 `running / waiting_approval` 的活动回合中，`record_approval_request` 单事务插入审批行、追加 `approval.requested`、更新回合为 `waiting_approval` 以及快照/版本。事件插入失败时审批行和回合状态一起回滚。审批 epoch 必须同时匹配当前审批 epoch 和已绑定上游 turn 的进程代次，旧代次请求被拒绝。

## 验证

执行 `python scripts/check.py`：16 份契约通过；134 项测试运行，129 通过、5 项因本环境链接创建或回环连接限制跳过。新增 3 项 Windows 行为测试覆盖共享连接打开失败后释放锁、旧双库文件阻止新库启动、审批行与事件原子提交、旧进程代次拒绝及事件失败回滚；现有审批行为测试继续通过。

尚未实现审批决定、派发及回合终态与事件库的完整同事务路径，也没有正式 Host API、旧进程隔离编排或双库迁移。审批内容关联、设备身份和权限范围仍需在应用服务中验证；不能将本切片当作产品审批已可用。
