# DEV-005 事件与快照事务切片

日期：2026-10-25。需求关联：FR-03、FR-06；协议章节：事件同步与历史、事件种类与投影；路线图：M1 事件与快照事务。当前仍处 M0，本记录仅是 M1 所需的独立存储前提，不表示 M0 退出或 Host 产品服务已可用。

## 实现与边界

- `EventJournal` 在同一 SQLite `BEGIN IMMEDIATE` 事务内分配每会话连续 `seq`、插入规范化事件、更新快照与 `last_seq`。提交后调用者才能发布事件；本切片本身没有发布器或 HTTP 长轮询。
- 两种排他游标分别读取增量与历史，历史响应按升序；每页最多 100 条、事件正文累计留出响应封装空间后低于 256 KiB，单事件最多 64 KiB。空增量页保持原游标。
- 快照从一行同时读取状态和 `last_seq`；不包含无界历史。存储启用外键、WAL、`synchronous=FULL`。本阶段初始数据库 `user_version=1`；后续活动槽切片升级为 v2，见 [记录](DEV-005-active-slot.md)。未知 schema 版本拒绝打开。
- 此处的 `snapshot` 和事件由调用方提供；尚无 Codex 通知映射、状态机校验、活动槽、事件发布、API、客户端缓存、迁移工具或生产数据升级方案。不能用此模块直接接收不可信网络字段。

## 验证

在本地 Windows 工作区执行 `python scripts/check.py`：16 份 Codex 契约校验通过；98 项测试运行，93 通过、5 跳过。新增 7 项测试覆盖跨重开持久化、快照更新失败后的事件插入回滚、双连接并发连续序号、双向排他分页、非法游标和字节边界。跳过项是本环境的链接创建与回环连接限制，与本切片无关。

尚未验证 Host 实际接入、长轮询唤醒竞争、真实上游通知顺序、生产数据库迁移或 Android 消费。进入 M1 集成时需将会话/回合/审批状态变化与该事务合并，而非在另一数据库事务中补写投影。
