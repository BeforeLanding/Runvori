# DEV-005 持锁启动原子恢复切片

日期：2026-10-25。需求关联：FR-02、FR-04、FR-09；路线图：M1 Host 启动与恢复。项目仍处 M0，本记录只证明本地持久状态行为。

## 实现与边界

- `LockedHostJournals.recover_host_after_isolation` 在持有 Windows 单实例锁的共享 SQLite 连接上执行。可信调用方须先确认旧受管进程已隔离，并提供旧 epoch、预期活动回合 ID/版本和中断原因；空库首次启动使用 epoch 0 和空活动回合。
- 入口在同一事务中核对 epoch 与活动槽，恢复旧审批及其操作，推进 epoch，然后把匹配的旧回合记为 `interrupted` 并释放活动槽。事件与快照按会话 seq 连续写入。审批或回合任一写入失败，连同 epoch、操作、活动槽一起回滚；不会出现只恢复审批却开放新回合的提交状态。
- 原有独立审批/回合恢复方法保留供技术探针使用；产品启动应调用统一入口，并在真实隔离、事务提交前保持写入口关闭。隔离证明本身、进程身份核对与 HTTP 写入口门控仍未实现。

## 验证

执行 `python scripts/check.py`：16 份契约通过；152 项测试运行，147 通过、5 项因本环境链接创建或回环连接限制跳过。新增行为测试覆盖空库 epoch 启动、未隔离拒绝、活动回合版本不符、派发中审批与旧回合一起恢复、跨重开状态以及回合中断事件插入失败时全部回滚。现有独立事件/审批恢复测试继续通过。

本切片不连接真实 app-server、进程 Job 或网络服务，不能据此认定旧进程已被隔离或产品重启安全性已验收。
