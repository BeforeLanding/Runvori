# DEV-005 共享库恢复前写门控

日期：2026-10-25。需求关联：FR-02、FR-04、FR-09；路线图：M1 Host 启动与持久状态。项目仍处 M0，本记录只证明本地存储入口的行为。

## 实现与边界

- `LockedHostJournals` 持锁打开 `host.db` 后先保持未恢复状态。共享 `EventJournal` 的公开写方法以及共享审批生命周期方法在 `recover_host_after_isolation` 成功提交前返回 `host_not_recovered`；读取已提交记录仍可进行。恢复尝试失败后门控继续关闭，重试成功才重新开放。
- `ApprovalJournal(connection=...)` 的旧独立探针写方法在共享连接上返回 `shared_store_requires_host_transaction`，避免不带规范化事件、操作或快照地改写审批。以独立数据库路径创建的旧探针继续保留原行为。
- 共享库公开的“只推进审批 epoch”恢复入口已移除。审批、操作、旧活动回合与 epoch 只能经持锁原子恢复入口一起提交。直接操作原始 SQLite 连接仍是内部信任边界，未来 HTTP 服务不得暴露它。

## 验证

执行 `python scripts/check.py`：16 份契约通过；152 项测试运行，147 通过、5 项因本环境链接创建或回环连接限制跳过。新增及调整的行为测试覆盖恢复前新会话/审批写入拒绝、共享审批旧写方法全部拒绝、恢复失败后事件与审批写入仍关闭、跨重开先只读查询再恢复、恢复后原操作重放，以及旧独立审批探针兼容。

尚未有真实 Host 服务、并发 HTTP 请求入口或操作系统级旧进程隔离证明。门控是单进程领域存储切片，不能单独证明进程树已经停止。
