# M0/Q-04：Windows 单实例锁验证切片

日期：2026-10-24，Asia/Shanghai。范围为 Windows 上 Host 数据目录单实例所有权的技术前提，不是已接入的产品 Host。

`host/src/runvori/infrastructure/instance_lock.py` 用已存在、由 Host 管理的数据目录中的绝对锁文件路径，持有文件句柄并通过 `msvcrt.LK_NBLCK` 对首字节获取非阻塞排他锁。获得锁前的失败一律拒绝继续；锁文件可留在目录内，是否能启动只由当前句柄上的锁决定，不根据文件是否存在或旧 PID 猜测。正常关闭解锁并关闭句柄；进程异常终止时操作系统释放句柄。当前实现只支持 Windows，要求调用方在整个 Host 生命周期持有对象。

真实跨进程测试：子进程持锁并写入就绪标记，第二进程尝试同一锁文件得到 `instance_lock_unavailable`；终止持锁子进程并等待退出后，新进程可获取锁。另测正常关闭后重取，且锁文件无需删除。夹具只在仓库忽略的 `.dev` 中运行，不使用用户工作区或模型账号。

在获准的本地执行环境执行 `python scripts/check.py`：16 份契约校验通过；82 项测试运行，80 通过、2 项因本机符号链接创建权限跳过，真实 junction 回归通过。`scripts/smoke_package.ps1` 同时确认该模块包含在当前 wheel 中，离线安装后的 CLI 返回 16 份契约校验通过。

限制：尚未在 Host 启动顺序中获取并保持锁，也未验证与 SQLite 活动槽、Job 进程所有权、数据目录权限和重启恢复的整体关系。此文件锁防并发启动，不是用户权限或文件系统攻击防护；锁路径父目录必须由 Host 管理。Q-04 仍开放。
