# DEV-005 新回合单次派发领取切片

日期：2026-10-25。需求关联：FR-02、FR-08、FR-09；验收前提：AT-08、AT-16。仍是 M0 阶段内的 M1 存储前提，不是可用的产品 Host。

## 实现与边界

- `claim_run_dispatch` 仅能将已受理的新回合操作从 `accepted` 事务性推进到 `dispatching`，同时追加 `operation.updated` 事件并更新会话版本。调用方必须在事务提交返回之后才尝试一次上游发送。
- `mark_run_dispatch_unknown` 仅能把已领取操作标记为 `unknown`，用于发送结果不能确认的情况；重复领取被拒，活动槽和 `starting` 回合保留，不能据此自动重试或启动另一回合。
- 已终态的回合不可再领取派发。事件插入失败时，状态、事件、快照和版本一并回滚。本阶段数据库 schema 为 v3；后续上游回合确认切片升级为 v4，见 [记录](DEV-005-turn-confirmation.md)。相同请求重放或查询返回当前操作状态。

## 验证

执行 `python scripts/check.py`：16 份契约通过；115 项测试运行，110 通过、5 项因本环境链接创建或回环连接限制跳过。新增 5 项行为测试覆盖跨重开后的单次领取与未知结果、双连接竞争、领取和未知标记的写入失败回滚，以及未领取/已终态拒绝路径。

尚未连接 Codex RPC、Host 单实例锁、受管进程隔离或上游 turn 证据；`confirmed / failed` 状态推进、重启核对和活动槽安全释放仍待集成。此切片只能保证数据库内的单次领取，不能单独证明上游操作已发送或执行。
