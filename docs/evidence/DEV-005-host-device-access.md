# DEV-005 恢复后 Host 与设备访问组合

日期：2026-10-26。需求关联：FR-01、FR-06；路线图：M1 Host 认证前提。项目仍处 M0。

## 行为

- `HostDeviceAccess` 只能从已持锁并完成统一恢复的 `LockedHostJournals` 创建；恢复前不创建或迁移 `pairing.db`。
- 组合层从权威 `host.db` 读取 `host_id`，以同一身份签发配对秘密、兑换设备令牌和构造鉴权读取网关。配对库只放在 Host 数据目录，链接或非文件路径被拒绝。
- 重建权威数据库产生新身份时，即使复制旧配对库，旧令牌也在进入邮箱前被拒绝；本地显式撤销后才能重新配对。
- Host 关闭后，旧组合对象拒绝签发秘密、撤销和读取；重开同一 `LockedHostJournals` 对象也不能复用先前组合的事件库归属。

## 验证与限制

`python scripts/check.py`：16 份契约通过；280 项测试运行，275 通过、5 项因本环境链接创建或回环连接限制跳过。新增 4 项 Windows 集成测试覆盖恢复门控、真实邮箱读取、重建身份与旧库、关闭后访问。`.\scripts\smoke_package.ps1`：离线 wheel 构建、隔离安装、已安装 CLI 契约校验和模块导入通过。`git diff --check` 无空白错误。

这是内部组合边界，还没有产品 Host 启动编排、HTTPS/TLS 端点、Android 连接或响应发送前复核。旧备份回滚检测与身份轮换仍需受信任恢复流程；仅凭新建数据库的随机身份不能判断回滚。Host 关闭与正在处理的请求并发时，最终网络响应仍须由未来适配层核验生命周期和设备授权。
