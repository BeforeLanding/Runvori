# DEV-005 内部事件等待取消边界

日期：2026-10-26。需求关联：FR-03、FR-06；路线图：M1 Host 事件同步前提。项目仍处 M0。

## 行为

- 可信调用方可以向内部增量事件等待传入 `threading.Event` 取消信号。已取消的请求在入队前拒绝；等待中可调用 `cancel_wait` 设置信号并唤醒请求线程，返回 `request_cancelled`。
- 读取已排队但 SQLite 所有者尚未处理时，调用方及时退出；所有者取出命令后跳过查询。读取已经完成时，请求线程在返回事件页前再次检查取消状态。
- 取消提示不产生持久事件，也不改变事件游标。取消信号由可信调用方持有；邮箱不自行判断设备身份或授权。

## 验证与限制

`python scripts/check.py`：16 份契约通过；259 项测试运行，254 通过、5 项因本环境链接创建或回环连接限制跳过。定向测试覆盖取消时已有事件、入队前取消、排队后且所有者读取前取消。

`.\scripts\smoke_package.ps1`：离线 wheel 构建、隔离安装、已安装 CLI 的 16 份契约核对及应用模块导入通过。

配对记录目前是独立探针，尚未与产品 Host 或内部邮箱连接。设备撤销及 Host 停止尚不会自动设置取消信号；未来 HTTP 入口还须在发送响应前重新核验设备权限，以处理取消与响应之间的竞态。当前没有产品 HTTP 服务或 Android 联调。
